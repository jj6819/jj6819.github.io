## Goal

Add a small control that lets users pick a **purpose for tomorrow**, and the calculator automatically:

* highlights the **best recommended cycle option** (4–6 cycles)
* adjusts how “strict” the bedtime suggestion feels (tight vs flexible)
* optionally suggests a **nap rescue** for “Survive” / “Recover”
* saves their choice (localStorage) so it sticks on return

Modes:

1. **Need to be sharp**
2. **Just survive**
3. **Recovery day**

## 4) Core logic: how Tomorrow Mode changes recommendations

You already compute 3 options: **4, 5, 6 cycles** with a 10-min wake window.

### Build “candidate plans”

When user sets wake time, you already compute bed windows like:

* for each cycle `c` in {4,5,6}:

  * `bedStart[c]`, `bedEnd[c]`

Represent candidates like:

```js
const candidates = [
  { cycles: 4, bedStart, bedEnd, sleepHours: ... },
  { cycles: 5, bedStart, bedEnd, sleepHours: ... },
  { cycles: 6, bedStart, bedEnd, sleepHours: ... },
];
```

### Ranking rules per mode (simple + feels smart)

**Need to be sharp**

* Recommend **6 cycles** if possible, otherwise 5, then 4
* Copy note: “Prioritizing more full cycles for performance.”

**Just survive**

* Recommend **5 cycles** (balanced)
* If user is generating this *late* (current time already past 5-cycle bedtime), recommend **4**
* Add “Nap rescue” suggestion: short nap tomorrow (20 min)

**Recovery day**

* Recommend **6 cycles**
* Also suggest either:

  * a **90-minute nap** window, or
  * an early bedtime + optional short nap

#### “Late right now” check (optional, sticky feature)

This adds real usefulness and retention:

* If it’s already past the recommended bedtime window, auto-downshift recommendation.

Example:

```js
const now = luxon.DateTime.local();
const missed = now > candidate.bedEnd;
```

### Suggested selection function

```js
function chooseRecommendedCandidate(candidates, mode) {
  const byCycles = (n) => candidates.find(c => c.cycles === n);

  if (mode === "sharp") return byCycles(6) || byCycles(5) || byCycles(4);

  if (mode === "survive") {
    const c5 = byCycles(5);
    const c4 = byCycles(4);
    // If bedtime for 5 cycles is already missed, recommend 4
    if (c5 && luxon.DateTime.local() > c5.bedEnd) return c4 || c5;
    return c5 || c4 || byCycles(6);
  }

  // recover
  return byCycles(6) || byCycles(5) || byCycles(4);
}
```

## 5) Add mode-specific “note” + optional nap suggestion

For the two modes that benefit from a nap hint:

### Nap heuristics (simple, non-medical)

Based on wake time tomorrow:

* **Power nap**: wake + 6.5 to 8 hours (typical midday dip)
* Duration:

  * survive: **20 minutes**
  * recover: **90 minutes** (one full cycle) or 20 minutes if user prefers short

Example generator:

```js
function napSuggestion(wakeTime, mode) {
  const start = wakeTime.plus({ hours: 7 });
  if (mode === "survive") {
    return { label: "Power nap", durMin: 20, start };
  }
  if (mode === "recover") {
    return { label: "Recovery nap", durMin: 90, start };
  }
  return null;
}
```

Render the note below results:

* Sharp: “Recommended: 6 cycles (performance-first)”
* Survive: “Recommended: 5 cycles (balanced). If you’re dragging, try a 20-min nap around 2:10 PM.”
* Recover: “Recommended: 6 cycles. Optional 90-min nap around 1:40 PM.”

(Use Luxon to format time in user locale.)

## 8) Wiring: hook buttons into your existing calculator

### Button events

```js
document.querySelectorAll(".tm-btn").forEach(btn => {
  btn.addEventListener("click", () => {
    const mode = btn.dataset.tm;
    setTomorrowMode(mode);
    document.querySelectorAll(".tm-btn").forEach(b => b.classList.toggle("is-active", b === btn));
    recalcAndRender(); // call your existing update function
  });
});
```

### On load

```js
const saved = getTomorrowMode();
document.querySelector(`.tm-btn[data-tm="${saved}"]`)?.classList.add("is-active");
recalcAndRender();
```
