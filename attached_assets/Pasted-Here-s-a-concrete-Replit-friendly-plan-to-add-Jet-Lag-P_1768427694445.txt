Here’s a concrete, Replit-friendly plan to add **Jet Lag Planner** as a **separate mode** alongside your existing sleep calculator, while reusing your current “Sleep Ticket → PNG download” pipeline.

## 0) Goal

Add a new mode that takes an itinerary (flight segments + layovers) and outputs:

* A **Jet Lag Ticket** (same 9:16 PNG style)
* A short, actionable **sleep plan** (2–4 blocks)
* A shareable link that reopens the plan pre-filled

## 1) Product shape

### Navigation

* Add a mode switch at the top:

  * **Sleep Calculator**
  * **Jet Lag Planner**
* Jet Lag lives at a new route:

  * `/jetlag` (or `/flight`)

### Output

* Same UI pattern you already have:

  * Preview card (ticket)
  * Buttons: **Download PNG**, **Copy share link**, **New Quote**, **Meme Mode** (if enabled)
* Add one new optional button:

  * **“Generate destination Sleep Ticket”** (takes arrival night suggestion → routes into existing sleep mode prefilled)

## 2) Data model

Represent itinerary as an array of segments:

```ts
type Segment = {
  fromAirport: string;   // "SFO"
  toAirport: string;     // "LHR"
  departISO: string;     // local time at fromAirport, stored as ISO with tz
  arriveISO: string;     // local time at toAirport
};
type Itinerary = {
  segments: Segment[];
  preferences: {
    canSleepOnPlane: boolean;
    style: "cycles" | "naps";
    targetDestinationBedtime?: "22:00" | "23:00" | "00:00";
    avoidSleepBeforeLandingMins: number; // default 75
  };
};
```

**Important:** store times as ISO with time zone context, not just raw strings.

## 3) Time zones + airports

### Airport to time zone mapping (practical options)

Pick one:

**Option A (fast + offline):** bundle a small JSON mapping for top airports

* `airports.json`: `{ "SFO": { "tz": "America/Los_Angeles", "name": "..."} }`

**Option B (better coverage):** use a lightweight airport dataset package (if your stack supports it)

* You just need `IATA -> IANA timezone`

### Time library

Use one that handles zones correctly:

* **Luxon** is simplest for “convert this local time in X zone to UTC and back”
* Or `date-fns-tz`

## 4) Algorithm (MVP that feels smart)

You don’t need a medical circadian engine—make it itinerary-realistic and consistent.

### Step A: Build “sleepable windows”

For each flight segment:

* Sleep window starts: `depart + 60m`
* Sleep window ends: `arrive - avoidSleepBeforeLandingMins` (default 75–90m)
  If window < 45m: ignore.

For layovers:

* If layover ≥ 2h45m: allow **one 25m nap** in the middle (optional label “airport nap”)

### Step B: Convert windows into destination time

* Decide a “destination reference zone” = timezone of final arrival airport
* Convert all sleepable windows into destination time for display and scoring

### Step C: Choose blocks

Goal: align sleep to **destination night** near arrival day.

* Destination “night window” default: 23:00–07:00 (or user preference)
* Score candidate sleep windows by overlap with destination night
* Fill with:

  * **90-minute cycles** (if style = cycles)
  * Or **25-minute naps** (if style = naps)
* Keep it to **2–4 blocks max** (simple output wins)

### Step D: Output format (ticket-ready)

Produce something like:

* Block 1: “Sleep 2 cycles” + start/end times (destination time)
* Block 2: “Sleep 1 cycle” OR “Power nap 25m”
* Block 3 (optional): “Stay awake last 75m before landing”
* Post-arrival note: “Stay up until ~22:30 local” (destination local)

## 5) Ticket rendering reuse

You already render a 9:16 ticket with:

* title (“Sleep Ticket”)
* bedtime/wake time
* personality label
* cycles count
* quote/meme slot

For Jet Lag Ticket, map fields like:

* Title: **“Jet Lag Ticket”**
* “Personality”: **Strategy** (e.g., “Arrive Morning Plan” / “Destination-Night Alignment”)
* Replace bedtime/wake:

  * “Main Sleep” (e.g., 01:10–04:10)
  * “Backup Nap” (06:30–06:55)
* “Cycles”: total planned sleep hours or “Planned Sleep: 4h 30m”
* Quote/meme slot stays identical

This means you mostly add a new “content adapter” layer:

* `buildSleepTicketData()`
* `buildJetLagTicketData()`

…and both feed the same renderer + PNG export.

## 6) Routing + state (Replit-friendly)

### Pages

* `/` → current sleep calculator
* `/jetlag` → new planner UI

### Share links

Use URL params to encode the itinerary:

* `?seg=SFO-LHR,2026-02-01T17:30,...&pref=cycles,...`

Two robust approaches:

* **Compressed JSON in URL** (base64 + gzip) for long itineraries
* **Short token** stored server-side (if you have a backend)

MVP: compressed JSON in URL.

## 7) Jet Lag Planner UI (MVP)

* Segment editor:

  * Add segment button
  * Each segment: From, To, Depart, Arrive
* Preference toggles:

  * Can sleep on plane (Y/N)
  * Cycles vs naps
  * Avoid sleep before landing (default 75m)
* “Generate Plan” button
* Output section: timeline list + Ticket preview + Download PNG

## 8) Testing checklist

* Same-timezone flights (no jet lag): should still propose reasonable “don’t sleep before landing”
* West→East vs East→West: destination night alignment behaves logically
* Red-eye that lands morning: suggests sleeping mid-flight and staying awake before landing
* Tight layover: no airport nap suggested
* Short flight: no cycles suggested, maybe “stay awake”

## 9) Implementation order (what to build first)

1. Add `/jetlag` route + skeleton UI

3. Implement sleepable window generation
4. Implement block selection + ticket data adapter
5. Wire to existing PNG download
6. Add share link encoding/decoding
7. Add “Generate destination Sleep Ticket” handoff

## 10) “Done” criteria (so you don’t overbuild)

* User can enter 1–3 segments, generate a plan, download a Jet Lag PNG
* Share link reopens the plan
* Ticket looks and behaves like your current ticket flow
